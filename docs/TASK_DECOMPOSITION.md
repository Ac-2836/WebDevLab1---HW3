# TASK_DECOMPOSITION.md - Resilient Event Hub (Homework 3)

This file defines the Work Breakdown Structure (WBS) and the atomic commit rules for Homework 3. Every sub-task is defined before any AI prompt is issued for it, and each sub-task maps to exactly one commit.

Assumptions: the countdown target is entered by the user as a local date and time, then stored as a UTC ISO 8601 string. The form has three fields: name, email and message. The submit request is simulated by a function that resolves after 1500 ms, and rejects when the email contains the text "fail".

## 2. Commit Rule

Each sub-task maps to exactly one atomic commit, in this order:

| #   | Commit message                                          | Task  | Files                                   |
| --- | ------------------------------------------------------- | ----- | --------------------------------------- |
| 1   | docs(spec): define landing page contracts and WBS table | DOC   | TASK_DECOMPOSITION.md, project-rules.md |
| 2   | feat(html): countdown markup                            | H3-01 | index.html                              |
| 3   | feat(js): drift-free countdown engine                   | H3-02 | countdown.js                            |
| 4   | feat(js): countdown rendering                           | H3-03 | main.js, index.html                     |
| 5   | feat(html): landing form markup                         | H3-04 | index.html                              |
| 6   | feat(js): form state machine                            | H3-05 | form-state.js                           |
| 7   | feat(js): form submit flow                              | H3-06 | mock-api.js, main.js                    |
| 8   | feat(js): double-submit guard                           | H3-07 | main.js                                 |
| 9   | feat(js): input sanitization                            | H3-08 | sanitize.js, main.js                    |
| 10  | docs(audit): AI failure mode report                     | H3-09 | AI_FAILURE_AUDIT.md                     |

Commit 2 and commit 5 contain no JavaScript file. Commit 3 and commit 6 contain no DOM access. Commit 8 changes only the submit guard in main.js. No commit may add 100 or more lines across multiple files without a matching WBS entry.
